## AI‑EVOLVE: Эволюционная Адаптация – итоговая документация

**AI‑EVOLVE** — прототип изометрической игры на **Panda3D**, построенный вокруг эволюции врагов, памяти, скиллов и модульной архитектуры с единичной ответственностью.

Проект сочетает две архитектурные линии:
- **Рабочий игровой цикл** на базе `EnhancedGame` (`src/main.py`) и сцены `EnhancedGameScene` (`src/scenes/main_game_scene.py`).
- **Расширяемая модульная архитектура** с компонентами и интегратором систем (`core/architecture.py`, `core/master_integrator.py`, `core/game_engine.py`), предназначенная для дальнейшего масштабирования.

---

## Концепция и реализованные механики

- **Роль игрока**: направляющий эволюции, влияющий на мир и врагов через действия персонажа и взаимодействие с окружением.
- **Бой и враги**:
  - Враги и боссы с несколькими типами (`basic`, `strong`, `elite`), поведением и параметрами.
  - Система урона, эффектов и скиллов реализована модульно в `systems/combat`, `systems/effects`, `systems/skills` и используется в сущностях.
- **Память и прогрессия**:
  - Системы памяти и эволюции (`systems/memory`, `systems/evolution`) реализуют хранение опыта игрока и общую память врагов (банки памяти).
  - Логика уровней, разблокировка скиллов и усиление врагов основаны на накопленном опыте.
- **Мир и окружение**:
  - Изометрическая сцена (`EnhancedGameScene`) с полем боя, стенами, деревьями, камнями и "объектами, создаваемыми игроком" (ловушки, сундуки, дополнительные враги).
  - Базовые подсистемы мира (`systems/world/*`) для времени суток, погоды, сезонов, навигации и окружения.
- **Инвентарь, торговля и социалка**:
  - Системы предметов, крафтинга, инвентаря, торговли и социальных взаимодействий реализованы как отдельные модули в `systems/items`, `systems/crafting`, `systems/trading`, `systems/social`, `entities/items.py` и связаны через `MasterIntegrator`.
- **UI и визуализация**:
  - Экран старта, HUD, экран смерти, меню и виджеты находятся в `ui/*`.
  - Система частиц (`systems/particle_system.py`), продвинутое освещение (`systems/advanced_lighting.py`) и единая визуализационная система (`systems/visualization/unified_visualization_system.py`) обеспечивают эффекты и улучшенный рендеринг.

## Архитектура проекта

- **`src/core`**
  - `architecture.py` — базовые понятия **компонента**, **жизненного цикла**, приоритетов и `ComponentManager`/`EventBus`.
  - `game_engine.py` — общий движок `GameEngine` на Panda3D, использующий `ComponentManager` и `MasterIntegrator`.
  - `master_integrator.py` — единая точка интеграции систем (атрибуты, бой, навыки, предметы, ИИ, память, квесты, торговля, мир, визуализация и т. д.).
  - `system_manager.py` — менеджер систем старой архитектурной линии (совместимость).
  - Остальные модули (`state_manager.py`, `repository.py`, `config_manager.py` и др.) обеспечивают хранение состояний, ресурсов и конфигураций.

- **`src/systems`**
  - `combat`, `effects`, `skills`, `items`, `memory`, `evolution`, `quest`, `trading`, `social`, `world`, `visualization`, `rendering`, `crafting`, `content` и пр. — модульные системы с чёткой ответственностью, регистрируемые в `MasterIntegrator`.

- **`src/entities`**
  - `character.py`, `enemy.py`, `bosses.py`, `mutants.py`, `npc.py`, `items.py` — игровые сущности, использующие системы атрибутов, боя, эффектов и памяти.

- **`src/scenes`**
  - `main_game_scene.py` (`EnhancedGameScene`) — основная сцена, на которой строится текущий игровой цикл: создание мира, игрока, врагов, HUD, логики смерти и маяка смерти.

- **`src/ui`**
  - Стартовый экран, HUD, экран смерти, управления паузой и настройки, единая UI‑система (`unified_ui_system.py`) и набор виджетов (`ui/widgets`).

## Текущий путь запуска и то, что реально используется

Фактический запуск игры сейчас идёт по цепочке:

- `run.bat` → `launcher.py` → `EnhancedGame` (`src/main.py`) → `EnhancedGameScene` (`src/scenes/main_game_scene.py`).

При этом:
- **`EnhancedGame`**:
  - Сам инициализирует Panda3D (`ShowBase`) и базовые компоненты (окно, камеру).
  - Поднимает `RenderSystem`, `EnhancedStateManager`, `ParticleSystem`, `AdvancedLighting`, `AudioSystem`, `PerformanceOptimizer`.
  - Регистрирует состояния: стартовый экран, игровую сцену (`EnhancedGameScene`) и экран смерти.
  - Ведёт собственный главный цикл с обработкой ввода, обновлением текущего состояния и рендерингом.
- **`GameEngine` + `MasterIntegrator`**:
  - Реализуют более общую и мощную компонентную архитектуру и полный набор игровых систем.
  - На данный момент **не подключены к `launcher.py`** и используются как фундамент для дальнейшего развития, а не как основной рантайм.

Это важно: **функциональность не дублируется**, а "новый движок" и интегратор уже готовы, но текущий прототип запускается на `EnhancedGame`. При дальнейшем развитии проекта можно перенести запуск на `GameEngine`, не теряя существующих систем.

## Установка и зависимости

### Требования

- **Python**: 3.8+ (рекомендуется 3.10+).
- **Обязательные библиотеки**:
  - `panda3d`
  - `numpy`
- **Базовые зависимости запуска** (описаны в `requirements.txt`):
  - `panda3d`, `numpy`
- **Дополнительные библиотеки для ML/аналитики** (описаны в `requirements_ml.txt`):
  - `torch`, `torchvision`, `scikit-learn`, `pandas`, `matplotlib`, `seaborn`, `numba`, `joblib`, `pillow`, `opencv-python` и др.

### Быстрая установка (Windows)

1. Создайте и активируйте виртуальное окружение (по желанию).
2. Установите основные зависимости:

```bash
pip install -r requirements.txt
```

3. (Опционально) установите ML‑зависимости:

```bash
pip install -r requirements_ml.txt
```

> `launcher.py` при запуске сначала проверяет `requirements.txt` и устанавливает зависимости только при изменении файла (или при `AI_EVOLVE_FORCE_REINSTALL=1`), затем выполняет проверку обязательных пакетов. Опциональные пакеты не блокируют запуск игры. Для AI/ML-подсистем используйте отдельную установку: `pip install -r requirements_ml.txt`. `run.bat` также выполняет установку `requirements.txt` перед запуском игры.

## Запуск игры

### Вариант 1: через `run.bat` (Windows)

В корне проекта:

```bash
run.bat
```

Скрипт:
- проверит наличие Python;
- установит зависимости из `requirements.txt`;
- запустит `launcher.py`.

### Вариант 2: напрямую через Python

В корне проекта:

```bash
python launcher.py
```

`launcher.py`:
- настраивает логирование и кодировки;
- проверяет версию Python и ключевые зависимости;
- создаёт необходимые директории (`logs`, `saves`, `assets/*`, `config`);
- инициализирует `EnhancedGame`;
- запускает игровой цикл.

## Управление и основные взаимодействия

В текущем прототипе (`EnhancedGameScene`):

- **ИИ-управление персонажем**: перемещение, выбор цели, автоприменение скиллов и автоподход к интерактивным сундукам выполняет AI-агент.
- **Действия игрока (клавиатура/мышь)**:
  - `Space` или `ЛКМ` — ручная атака ближайшего врага.
  - `E` — взаимодействие с объектами (сундуки теперь также открываются автоматически при подходе персонажа).
  - `1` — выбрать режим и создать врага рядом с игроком.
  - `2` — выбрать режим и создать ловушку рядом с игроком.
  - `3` — выбрать режим и создать сундук рядом с игроком.
- **Пауза и меню**:
  - `P` — пауза/возобновление (через систему состояний и/или оверлейное меню).
  - В экране смерти (`DeathScreen`) доступны кнопки: **Restart**, **Main Menu**, **Exit**.

## Что ещё важно знать о реализации

- **Системы в `core` и `systems` соответствуют плану из `plan.txt`**: атрибуты, эффекты, скиллы, урон, память, эволюция, квесты, торговля, социальные связи, мир, визуализация, здания и т. д. — всё вынесено в отдельные модули с единичной ответственностью.
- **Часть систем сейчас выступает как "каркас"**:
  - `MasterIntegrator` создаёт и интегрирует все системы, но бо́льшая часть геймплейных сценариев в прототипе проходит через `EnhancedGameScene` и связанные с ним сущности.
  - Это сделано умышленно, чтобы не создавать дублирующие модули: новая архитектура расширяет и связывает уже существующие файлы, а не переписывает их с нуля.
- **Файлы сохранений и памяти** (`saves/*.json`, `*.pth`) используются для хранения "памяти" ИИ и состояния сессий; формат можно расширять без изменения основной логики.

## Итоги проверки и возможные точки развития

- **Основной путь запуска согласован**: `run.bat` → `launcher.py` → `EnhancedGame` → `EnhancedGameScene`.
- **Архитектурный каркас завершён**: `GameEngine` + `MasterIntegrator` + `ComponentManager` + модульные системы покрывают запрошенную в `plan.txt` архитектуру.
- **Потенциально неиспользуемые/частично используемые подсистемы**:
  - Некоторые системы из `systems/*` пока не задействованы напрямую в `EnhancedGameScene` и предназначены для следующих этапов (квесты, сложные социальные взаимодействия, здания и т. д.).
  - Это не ошибка, а задел под расширение: при необходимости их можно подключать через `MasterIntegrator` или адаптеры к текущей игровой сцене.

Документация отражает фактическое состояние проекта и путь запуска. При дальнейшем развитии имеет смысл сфокусироваться на полном переходе рантайма на `GameEngine`/`MasterIntegrator`, используя существующие системы, а не создавая новые дублирующие модули.

## Аудит кода (2026-03, обновлено)

В рамках повторного технического аудита подтверждено «синтаксическое здоровье» проекта.

Проверка синтаксической корректности Python-кода по входной точке и всему дереву `src`:

```bash
python -m compileall -q launcher.py src
```

Дополнительная smoke-проверка импортируемости стартового модуля:

```bash
python -c "import launcher; print('launcher-import-ok')"
```

Дополнительно выполнена быстрая AST-проверка исходников (без запуска игрового цикла), чтобы убедиться в отсутствии синтаксически повреждённых файлов:

```bash
python - <<'PY'
import ast
from pathlib import Path
for p in [Path("launcher.py"), *Path("src").rglob("*.py")]:
    ast.parse(p.read_text(encoding="utf-8"), filename=str(p))
print("ast-ok")
PY
```

Результат аудита:
- ошибок синтаксиса не обнаружено;
- в средах без GPU/GL (например, CI/контейнер) запуск автоматически переходит в headless-режим вместо аварийного завершения по `No graphics pipe is available`;
- критические `SyntaxError`/`IndentationError`, ранее встречавшиеся в повреждённых модулях (`core`, `entities`, `systems`, `ui/widgets`), не воспроизводятся;
- модуль запуска импортируется корректно;
- код `launcher.py` совместим с заявленной минимальной версией Python 3.8+ (без использования синтаксиса аннотаций `list[str]`);
- добавлены и проходят smoke-тесты:

```bash
pytest -q
```

Примечание: модуль `src/systems/testing/test_system.py` является частью игрового кода, а не набором pytest-тестов; автоколлекция pytest для него отключена через `__test__ = False`, чтобы избежать ложных предупреждений и нестабильных проверок.
